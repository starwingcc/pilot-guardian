两案共同的实现含义

  1. 方案 A 全部基于现有 status:get（rule + evaluation.reason + nextChangeAt），仅深链编辑需控制台支持 ?rule=<id> 预选参数。
  2. 方案 B 需要新增 status:get-all 消息：后台遍历启用规则执行现有 evaluatePolicy，只返回 PublicAccessRule，挑战答案不出后台。
  3. 挑战答案等敏感字段继续留在后台；两案均不新增「快速绕过」类动作，保持有意识的访问摩擦。
  4. 印章色彩沿用语义：绿 = 放行窗口、琥珀 = 挑战、红 = 冷却 / 关闭，与闸门页文案语义一致。
